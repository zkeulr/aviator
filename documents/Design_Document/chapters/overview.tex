\subsection{Integration Approach}
The system integrates an ADS-B software-defined radio (SDR), a cloud data pool,
a local processing subsystem, a display module, and a power management
subsystem. The ADS-B SDR publishes raw flight data to the cloud pool;
the processing subsystem ingests that cloud stream plus external APIs
and user inputs, normalizes and filters the data, and forwards compact
display updates to the display module. The power management subsystem
supplies energy to the processor and display and includes a battery
backup to preserve state and reduce startup latency.

Design priorities are resilience and graceful degradation: if network
connectivity is lost the device continues to show local time and the last
cached flight/weather state; if power to the device is interrupted the
ADS-B transmitter can still upload to the cloud independently. Data is
cached locally and keyed by timestamp so that, on reconnection, the
processor can quickly reconcile and display missed updates. Interfaces
are defined around simple, versioned JSON payloads and REST/WebSocket
endpoints to minimize coupling and simplify testing. Latency, cache
expiration, and failure modes are documented per interface to guide
integration testing.
