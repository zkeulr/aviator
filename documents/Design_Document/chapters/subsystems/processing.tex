% Algorithm
\subsubsection{Algorithm}
\begin{lstlisting}
    initialize clock, network, display, location
    DATA = {}

    always 
        wifi keep alive
        error handling
        if power button pressed
            save and shut down
    
    every minute
        update display time

        read ADS-B sensor
        if ADS-B valid
            add to DATA
            if internet connected
                upload ADS-B data
            else
                cache ADS-B data
        else 
            if internet connected
                make API call for flight data
                add to DATA
            else
                add warning ADS-B out of date to DATA
            

        if battery powered
            update battery level in DATA

        update time, weather in DATA
        convert DATA to pixel buffer
        push pixel buffer to displar
    every hour
        sync with network time
        make API call for weather

\end{lstlisting}

\subsubsection{Theory of Operation}
The processing subsystem is responsible for
coordinating all other subsystems and serving
as the “brain” of the Aviator device. At startup,
the ESP32-S3 initializes its real-time clock,
connects to the Wi-Fi network, and
configures the SPI interface for display communication.
During normal operation, the processor maintains a
persistent network connection to ensure timely access
to APIs.

Every minute, the processor updates the displayed time,
retrieves the latest flight information from the network
subsystem, and parses the response into a standardized
data structure. If the device is battery-powered, it
also queries the power management subsystem for voltage
information and appends this to the displayed data.
The processor then converts the compiled information
(time, weather, and flight updates) into a pixel buffer
and transmits it to the display subsystem.

On an hourly basis, the processor synchronizes the
real-time clock with network time servers and fetches
weather data for local context. Error handling
routines ensure that loss of network, corrupted data,
or power fluctuations do not crash the system; instead,
the subsystem retries API calls or falls back to cached
data, with a warning that the data is out of date.

% Specification Measurement
\subsubsection{Specifications Measurement}
\begin{enumerate}
    \item \emph{Clock drift $\leq \pm 1\frac{\text{sec}}{\text{day}}$}.

          We measured drift over a period of two days with the following script:
          \begin{lstlisting}[language=Python]
    import time, board, rtc, wifi, socketpool, adafruit_requests
    pool = socketpool.SocketPool(wifi.radio)
    requests = adafruit_requests.Session(pool, None)
    r = requests.get("http://worldtimeapi.org/api/ip")
    ref = r.json()['unixtime']
    r.close()
    dev = rtc.RTC().datetime 
    dev_epoch = int(time.mktime(dev[0:6] + (0,0,0))) 
    print("offset_s", dev_epoch - ref)
    \end{lstlisting}
          Reported drift was 1.44 seconds, or 0.72 seconds per day, within tolerance.
    \item \emph{After network interrupt, system must reconnect within 120 seconds upon network resumption.}

          This was tested by disabling the Wi-Fi hotspot to which the device was
          connected, waiting 60 seconds, and renabling. Device reconnected in 50 seconds.
          By design, the device will always try to reconnect once a minute if disconnected.
    \item \emph{System must run with zero memory leaks.}

          We tested this by enabling heap logging via the \texttt{gc} module and tracking over
          three days while device was in normal operation. Free memory
          was observed to not have a monotonically decreasing trend beyond noise;
          upon initialization, free memory was reported as
          \texttt{8274912} and after three days free memory was still
          reported as \texttt{8274912}.
    \item \emph{System must never display text overrunning borders.}
          This is accomplished with bounds checking and scrolling text that
          overflows bounding box. Tested with random strings up to
          65 characters long.
\end{enumerate}
