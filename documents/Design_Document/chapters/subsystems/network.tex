% Specifications
\subsubsection{Specifications}

\textbf{Wi-Fi \& Internet Connectivity}
\begin{enumerate}
    \item Connection to WPA2 network established in less than 10 s.
    \item HTTPS request latency less than 500 ms for payloads up to 2 kB.
    \item Outbound HTTP POST/GET success rate at least 95\%.
    \item Fallback mode automatically activates within 5 s if connectivity is lost.
    \item Error handling uses up to 3 retries with exponential back-off before fallback.
    \item System connectivity uptime at least 95\% during a continuous 1-hour runtime.
\end{enumerate}

\textbf{ADS-B Reception}
\begin{enumerate}
    \item Receives ADS-B messages over HTTPS from a remote decoding server.
    \item Retrieval latency less than 500 ms per request.
    \item API update frequency between 1–2 Hz (matching typical ADS-B refresh rate).
    \item Data integrity ensured via JSON schema validation and CRC-validated ADS-B frames from the upstream server.
    \item Missing-data tolerance: subsystem enters degraded-mode if ≥ 5 seconds pass without ADS-B updates.
\end{enumerate}

\textbf{GPS (Optional)}
\begin{enumerate}
    \item Provides 1 Hz location fix rate.
    \item Supplies location and time data to synchronize ADS-B and API results.
\end{enumerate}

% Interactions
\subsubsection{Subsystem Interactions}
The Communications Subsystem acts as the Aviator’s data bridge between external information sources and the internal electronics. It collects ADS-B data (via HTTPS), airport-information API responses, and weather API data, then forwards validated information to the Processing Subsystem over UART or SPI for formatting and display rendering.

Power is provided by the Power Management Subsystem through a regulated 3.3 V rail, ensuring stable operation of the ESP32 and associated communication hardware. The ESP32 can also report basic voltage or connectivity status back to the power subsystem as needed.

Externally, this subsystem interacts with:
\begin{itemize}
    \item An online ADS-B server providing decoded aircraft position, velocity, and identification data.
    \item The Open-Meteo weather API.
    \item Airport-information APIs.
\end{itemize}

All ADS-B demodulation and decoding of raw I/Q samples is performed externally (e.g., on a host PC or remote server). The ESP32 retrieves only the decoded data frames through periodic HTTPS requests.

% Algorithm
\subsubsection{Algorithm}

This subsystem uses a multi-threaded structure that handles ADS-B retrieval and weather updates concurrently.

\textbf{ADS-B Processing Pipeline}
\begin{enumerate}
    \item \textbf{Data Acquisition:} Retrieve decoded ADS-B messages from an external HTTPS server.
    \item \textbf{Validation:} Apply JSON schema checks and ensure upstream CRC validation.
    \item \textbf{Message Classification:} Use Type Codes (TC 1–4, 9–18, 19) to determine message type.
    \item \textbf{Position Decoding:} Apply Compact Position Reporting (CPR) algorithms if raw coordinates require even/odd frame pairing.
    \item \textbf{Database Management:} Maintain active aircraft records indexed by ICAO address.
\end{enumerate}

\textbf{Weather Integration}
\begin{enumerate}
    \item Issue HTTPS calls every 15 minutes to retrieve surface and upper-air data.
    \item Parse fields including temperature, wind, and pressure at multiple atmospheric levels.
    \item Correlate weather data to aircraft positions for contextual flight information.
\end{enumerate}

\textbf{Flight Database Correlation (Future)}
\begin{enumerate}
    \item Callsign lookup using OpenSky or FlightAware.
    \item Route and delay correlation using external scheduling APIs.
    \item Enhanced visualization of flight metadata.
\end{enumerate}

\textbf{Data Fusion and Export}
\begin{enumerate}
    \item Compute aircraft distance from receiver using geodesic formulas.
    \item Apply retry handling for malformed frames and API failures.
    \item Export fused data via high-level APIs to downstream processing.
\end{enumerate}

% Theory
\subsubsection{Theory of Operation}
On startup, the ESP32 connects to Wi-Fi and immediately begins polling an external ADS-B decoding server. Each HTTPS GET request retrieves a JSON payload containing aircraft ICAO addresses, positions, velocities, and timestamps.

Simultaneously, the ESP32 issues periodic HTTPS requests to the Open-Meteo API for weather conditions at surface and upper-atmosphere levels. If GPS is included, the module provides a synchronized 1 Hz fix for correlating ADS-B tracks with real-world position and time.

The subsystem runs continuously with:
\begin{itemize}
    \item Failover behavior if connectivity is lost.
    \item Retry logic (three attempts with exponential backoff).
    \item Database pruning to remove stale aircraft entries.
\end{itemize}
